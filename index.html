TL;DR

Let a small model make the routine choices of an agent

Most steps of an LLM agent end in a multiple-choice decision, such as which tool to call next. A small decision model can answer many of them in a fraction of an LLM call's time and price. We test such models inside running agents, deploy them behind a confidence threshold fitted on the agent's own trajectories, and train an open 4B model on the states an agent actually visits.

Abstract

Large language model (LLM) agents now fix software, operate computers and serve customers, but their harnesses, the programs that run them, call a large LLM at every step, which makes long tasks slow and costly. Most of these calls end in a multiple-choice decision, such as which tool to call next. Decision models such as Jev answer these questions directly, at a fraction of an LLM call's time and price. We ask how a harness can delegate these decisions to a decision model with little loss of success. To evaluate decision models in agentic tasks, we build AgentDecisionBench, which tests them from isolated questions up to control of a running agent, on public benchmarks and our DecisionGym environment. The decision model most accurate on isolated questions solved only 69.5% of agent tasks, and without a fitted confidence threshold, delegating tool choices lowered success by 19.0 points. Building on these findings, we then design JevAgentHarness, which fits this threshold for each choice on the agent's own trajectories and lets the LLM decide below it. Because existing decision models never see the states an agent reaches after its own mistakes, we train AgentDecision-4B, an open 4B model, on such states with Jev's answers as labels. On tasks unlike its training data, the agent solved 91.5% of them with AgentDecision-4B and 82.0% with Jev. On tasks like their training data, 4B models trained this way made agents 81.1-89.0% cheaper and up to 2.5 times faster, without losing 3 or more points of task success. The models, data, and harness will be released at https://github.com/JevAgentHarness/JevAgentHarness.

Method

Three parts: evaluate, deploy, train

Each part answers one question. Which decision models work inside an agent? How should a harness use them? Can a small open model learn the decisions?

Benchmark

AgentDecisionBench

Tests decision models at three levels, each closer to real use, on public benchmarks and on DecisionGym. DecisionGym is a customer-service environment that knows the acceptable next steps at every state, so each choice can be scored.

  • L1Isolated questions. One question with no agent around it.
  • L2Step level. States from recorded agent runs. Answers are scored but not carried out.
  • L3Task level. The model makes a running agent's choices. Scored by task success.
Dataset on Hugging Face
Harness

JevAgentHarness

Puts a decision model into an existing harness. At a decision point the harness asks a typed multiple-choice question. It uses the answer only when the model's confidence clears a threshold fitted on the agent's own logs. Below the threshold, the LLM decides.

Model

AgentDecision-4B and -0.8B

Existing decision models never see the states an agent reaches after its own mistakes. We train on exactly those states, with Jev's answers as labels. AgentDecision-0.8B applies the same recipe to StartLux-Decision-0.8B.

  1. Agent states labelled with Jev's answers
  2. SFT learns Jev's answers
  3. GRPO rewards success with fewer LLM calls
  4. Public tool-use data for the released 4B model

Open-source proxy

Routing for coding agents, with no change to the agent

JevAgentHarness also ships as a local OpenAI-compatible proxy. Codex, pi, DeepSeek Harness, mini-swe-agent and Terminus-2 work through it unchanged.

  1. The harness sends each model call to the proxy instead of the provider.
  2. A decision model reads the agent's state and answers one question: is the next step routine or hard?
  3. Routine steps go to a fast model and hard steps to the strong one. The first step and the decision that the task is done stay on the strong model, and any error falls back to it.
  4. Every step is logged with its tier, tokens, cost and latency, so jah report shows the saving on your own tasks.

Quickstart

Route your coding agent in three steps

The proxy holds the provider keys. Your harness gets a local URL and a dummy key, so keys never enter the agent's sandbox.

1

Install and start the proxy

git clone https://github.com/JevAgentHarness/JevAgentHarness.git && cd JevAgentHarness
pip install -e .
export GEMINI_API_KEY=...              # the LLM tiers (Gemini by default; any OpenAI-compatible API works)
export OPENROUTER_API_KEY=...          # the decision model (Jev on OpenRouter); or use {type: rules}, no key
jah init                               # optional: writes ~/.jah/config.yaml (commented) to edit
jah serve                              # http://127.0.0.1:8787/v1, uses ~/.jah/config.yaml if it exists
2

Point your harness at it

Use the base URL http://127.0.0.1:8787/v1, any dummy key and the model name jah-auto. jah setup <harness> prints the snippet for your harness.

jah-autorouted: the decision model picks the tier for every step
jah-strongevery step on the strong tier (your baseline)
jah-fastevery step on the fast tier
~/.codex/config.toml
model_provider = "jah"
model = "jah-auto"
web_search = "disabled"

[model_providers.jah]
name = "JevAgentHarness"
base_url = "http://127.0.0.1:8787/v1"
env_key = "JAH_API_KEY"
wire_api = "responses"
stream_idle_timeout_ms = 600000
JAH_API_KEY=jah codex exec --skip-git-repo-check "fix the failing test"
jah.patch.yml
- id: llm-pi-ai
  config:
    providers:
      jah:
        api: openai-completions
        baseURL: "http://127.0.0.1:8787/v1"
        apiKeyEnv: JAH_API_KEY
        compat: {supportsStore: false}
        models:
          - {id: jah-auto, contextWindow: 1000000, maxTokens: 65536}
- id: agent-default-model
  config: {provider: jah, model: jah-auto}
JAH_API_KEY=jah dsh --profile headless --patch jah.patch.yml "fix the failing test" --json
~/.pi/agent/models.json
{"providers": {"jah": {"baseUrl": "http://127.0.0.1:8787/v1", "api": "openai-completions", "apiKey": "JAH_API_KEY",
  "models": [{"id": "jah-auto", "reasoning": true, "contextWindow": 1000000, "maxTokens": 65536}]}}}
JAH_API_KEY=jah pi --provider jah --model jah-auto "fix the failing test"
jah.yaml
model:
  model_name: openai/jah-auto
  model_kwargs: {api_base: "http://127.0.0.1:8787/v1", api_key: jah}
  cost_tracking: ignore_errors    # litellm has no price for jah-*; the proxy logs the cost
mini -c mini.yaml -c jah.yaml -t "fix the failing test"
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8787/v1", api_key="jah")
client.chat.completions.create(model="jah-auto", messages=[...], tools=[...])

For litellm-based agents, use the model openai/jah-auto with api_base="http://127.0.0.1:8787/v1".

3

Measure the saving on your own tasks

Run the same task with jah-strong and jah-auto, then compare them. Shadow mode logs what every decision point would do without changing anything, and jah fit fits the thresholds on those logs.

jah report ~/.jah/logs            # per model name: sessions, steps, strong share, $ and LLM seconds per session
jah serve --preset shadow         # every point logs its answer next to what the agent did; nothing changes
jah fit ~/.jah/logs               # fit each point's threshold on those logs and print a config snippet
